## Ask

| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `circles`                   | abort this task, summarize the work in 'aborted.md' begin an an breakdown                                                                                                                                           |

| `help`                      | Show this table                                                                                                                                                                                                     |
| `memory`                    | Describe any useful auto-generated insights from userMemories (normally ignored?)                                                                                                                                   |
| `missing`                   | is anything inconsistent, innaccurate, incomplete, vague or in any way not ready for X?                                                                                                                             |
| `murky`                     | carefully **review** the chat so far                                                                                                                                                                                |
| `plain`                     | translate using only plain english and our lexicon. do not use technical or mathematical terms without first defining them. offering to add them to our lexicon                                                     |
| `propose`, `proposal`, `p`  | describe co's plan and do NOT execute it                                                                                                                                                                            |
| `rate`                      | read `.claude/hooks/murk.jsonl`. report complaints per 100 replies, and the change since the last time it was asked. then append a new line to `memory/shared/zone/work/murk journal.md` -> date, replies, complaints, rate           |
| `ready`                     | is X robust, reliable, well organized, guaranteed to work?                                                                                                                                                          |
| `instruction`, `i`          | (a file name, line number, Jonathan's correction or the chat so far). analyze X (original and correction) and write an instruction that, when applied by co to the original, produces the correction                |
| `rewind`                    | synopsis of what we are working together on                                                                                                                                                                         |
| `simplify`                  | say the last reply again with fewer moving parts: fewer clauses, fewer names, one idea per sentence                                                                                                                 |
| `start`                     | orient per "Session protocol" in `memory/shared/truth/handbook.md`: root index → handbook → project index → lexicon → matched truths → questions (read, never reported). Reply with the two-line orientation        |
| `summary`                   | the state of this chat, with extreme brevity: done, in motion, open. A handful of lines, no preamble, no recap of how we got here                                                                                   |
| `tokens`                    | crude (rough, loose) estimated percentage of context consumed (okay with Jonathan that no exact measurement is available, just give a number)                                                                       |
| `translate`, `rewrite`, `t` | Rewrite the last response using concise, plain english. Use the standard term; avoid the decorative one.                                                                                                            |
| `understand`, `u`           | are Jonathan's instructions clear and complete? answer 'yes' or 'no what is X?' Jonathan is wary of downstream disasters caused by misunderstanding                                                                 |
| `where <X>`                 | name the one file that owns X, per "Finding where to tweak" in `memory/shared/truth/handbook.md`; two claimants = duplication bug, report both                                                                      |
| `wordy`, `w`                | translate using careful choice of words — the way Jonathan writes, almost all the time                                                                                                                              |

## File edits

| Command           | Action                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `check`           | audit the memory system per the `check` entry in `memory/shared/truth/handbook.md` (Skills section). Report finding → file → fix; fix nothing unless told                                                                                                                                                                                                                                                                |
| `cleanup`         | after files or folders move inside `memory/`: re-point every link the move broke, resolved against its old place, never one already dead; fix `CLAUDE.md`, the hooks, `shorthand.md`, `keywords.md`, `gates.md`, the project's map and index; drop what the move emptied; run vitest, svelte-check and the dispatcher's test, fixing what broke; log it with one `D:` line naming what moved and what still needs a hand |
| `consolidate`     | consolidate the active project's log per "Consolidate" specified in [[handbook]] — all steps, nothing deleted from the log, and NEVER a git commit; finish with a tabulated manifest (each line and where it went) in the chat                                                                                                                                                                                                                         |
| `debt`            | run `python3 tools/code_debt.py`, which writes `memory/shared/zone/code debt.md`, one line per memory file holding unfinished work. Reply with the line count it prints and the file's path, and a total line count in the H1 at line 1                                                                                                                                                                                  |
| `decide`, `d`     | add a row to ...                                                                                                                                                                                                                                                                                                                                                                                                         |
| `drive <X>`       | make proposal X the drive: X names a `##` section in the current project's proposals.md or a zone file of its own, open or decided, nothing required of its words. Everything below `zone/drive.md`'s Current state is replaced by the proposal's text under its heading plus a **Current status:** line; the proposal leaves proposals.md, or its file is deleted through the dispatcher, its index line with it; the plan replaced goes into the work journal under its old heading; one `D:` line |
| `drive`, `go drive` | implement the plan in the current project's `zone/drive.md`; then move the proposal to `truth/working features.md` rewritten as a feature description when it is an app feature, or else to the work journal as a description of what was changed and why; one `D:` line |
| `define <X>`      | coin or redefine term X (see "Prose and terminology" in [[handbook]]) — lexicon entry + `D:` log line in one act; co's only entry point into lexicon                                                                                                                                                                                                                                                                     |
| `egads`           | Jonathan is extremely disappointed and has far less trust that collaboration can succeed. add the current mess to learn                                                                                                                                                                                                                                                                                                  |
| `finished`, `fin` | run `python3 tools/finished.py`, which writes `memory/shared/logs/finished.md`, one line per memory file holding finished work. Reply with the line count it prints and the file's path, and a total line count in the H1 at line 1                                                                                                                                                                                      |
| `fix`             | analyze explanation of a bug, and precisely fix it                                                                                                                                                                                                                                                                                                                                                                       |
| `full log`        | re-assemble the active project's `logs/log.md` from git, every line ever written: list its commits and paths with `git log --follow --format=%H --name-only -- memory/<X>/logs/log.md`, read each version with `git show <commit>:<path>`, gather every `- ` line and its indented lines under its `## <day>` heading, each once, newest day first; the file as it is on disk counts as the newest version; write the file anew with its H1 and marker kept; one `D:` line saying how many lines over how many days, from how many versions |
| `go`              | proceed with proposal as stated                                                                                                                                                                                                                                                                                                                                                                                          |
| `learn`           | Summarize the mistake co just made as one checkbox line in `memory/shared/zone/learn.md`, or the project's own, in co's words, replacing a line already saying something close; report how many corrections wait |
| `mothball`        | state and confirm the specifics of the current context. then gather everything relevant into a mothball file                                                                                                                                                                                                                                                                                                             |
| `pause`           | add the current context to the current project's `zone/work/current context`                                                                                                                                                                                                                                                                                                                                             |
| `record`          | **move to work journal** -> every checked box in  {ideas, drive, code debt} and every decided proposal. **move to truth** -> every checked correction in `zone/learn.md`, by hand, each leaving a row in `memory/shared/logs/distilled.md`, the pattern and where its rule went; the tool leaves learn.md alone. Update work journal, working features, and map. Execute finished. Reply with what moved. `record` needs a merge step or a sub-folder before it runs on a big done folder, and co says what it is about to move first |
| `setup`           | for the current project, create whatever `zone` folder's files are missing per the minimal set in `memory/shared/truth/workflow.md`: always add `ideas.md`, `drive.md`. add the rest only when asked. NEVER overwrite an existing file; report what got created                                                                                                                                                          |
| `undo`, `revert`  | Revert last file change                                                                                                                                                                                                                                                                                                                                                                                                  |
