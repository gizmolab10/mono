# Controls in the UX

The collections are T_Bundle's — mu since 29 August, mj and gallery since 1 September — and the dispatcher lists each one's files and its top CLAUDE file. The memory system is a collection in the projects filter, but a file's project is its own idea (`project_of`): a memory file whose first folder names a collection answers to that project — memory/mu to mu — and only shared/ and folders naming no collection stay memory's. Matching, sorting and the project column all go by it. Memory files carry their own bundle; the memory/ prefix is stripped from their paths. In the folder view a memory file hangs under the top of the project it answers to, its folders beside the guides — memory/ov/truth shows as ov → truth — and no folder is made for the project's own name; each folder keeps its full path, so its place on disk and index repair are unchanged.

The list's filters hold four stacked sections — search, projects, kinds, tags — each with its clickable on the line above it; the search clickable, folded, says what is typed, and the folded '✂ filters ➜' readout leads with the search text. Each search line carries a centered 'clear', drawn only while there is text to clear; both fields are plain text inputs, the browser's own cross gone. Emptied search words take their highlight with them — Search watches the value itself. The heavy '✂ filters' line sits on the region's top edge, its clickable poking above the border, matching the editor's.

When the search text leaves a section nothing to offer, an unfolded projects, kinds or tags section takes a fold's height and its centered clickable is replaced by a label, not pressable, reading 'no options for current search', drawn as the clickables are: the same edge, pill and page-colored fill masking the line.

Projects allow more than one pick. Empty means all. The project column shows unless exactly one is picked. The row is two seg controls that wrap as the tagsets do — side by side one `--gap` apart while both fit inside the section, otherwise one above the other one `--gap` apart, each row centered: `mo`, `core`, `gallery` and `shared` lead in the first, every other project follows in the second. One snippet draws a group and is rendered twice, so the two can never differ; a group the other filters leave empty is not drawn at all. The table ends with a right-justified size column at `--font-tiny`: a file's character count read at launch, a folder summing its matching files, written through `in_thousands` (38392 → 38.4k), sortable with numbers padded so 9 sorts before 80. The kinds row offers only kinds with matches; a picked kind that loses its last match clears itself. Its `none` segment, there only while something answers it, matches a file with no labels at all or with labels naming no kind — the files the kind column draws as `---`.

The option-click ladder, on every multi-select control: plain click toggles one; option-click keeps only that one, inside its own control (one tagset); command-option-click keeps only that one everywhere. hit_target hands every press its mouse state, so held keys can be read.

An open tagset's segments follow the area's own order in Tag_Areas.ts — lifecycle reads born, weighed, waiting, incorporated, and active reads now, next, soon, later, tabled; the other areas are listed alphabetically. Indents: sub-filter clickables stand in from the edge by --gap-big; a child row in the files list indents by --gap-big per level. A row's soft pointer shows nothing under the cursor; only the header's fills. The header's pointer is drawn only while the folders show and more than one root folder does — with one root, that root's own pointer shuts everything under it — and it sits in a slot the width of a row's at the name cell's start, centered on the header's line, so it lines up with the root rows' pointers. An open folder's name reads `--gray`. Each row's tags end with the picked tags, in the picked order, so the right edge matches the tags filter.

Every background that lights fades in and out, two timings said once in main.css. Buttons, pills, clickables and a row of the list take `--hover-fade`; a whole section's background — section bodies, a stack's slots, the tag areas' bare space, the editor's filter block — takes `--hover-fade-section`, twice as slow, since it moves far more color.

In both filter stacks the slot the stack gives a section holds the stack's half-gaps as its own padding, and a section that answers the cursor says so in its Stacked entry — the hit target's name, kind, press and tip, and whether it is highlighted — so the stack puts the target and the fill on the slot itself; no row reaches over the half-gaps, and no filter file names `--over` or `--under`. A row's breathing gap is plain padding in a rung. Both tags runs hold a small gap of margin above themselves always, so a tagset's name riding above a pill in the top row sits clear of the line overhead; nothing measures whether one rides.

While a file is open, the row across the top holds the file's controls — the count, the steppers, the folders, the name field, the four file buttons and the delete question — as a section of its own right of the way back: past a heavy upright line with no hairline, on the page color with rounded corners, as tall as the hamburger, which sets the row's height; the back button is two pixels smaller than the steppers' triangle. The dispatcher and build buttons are not drawn then. The section's bare space answers nothing — no press, no highlight; the way back is the button beside it. The form's rows — search, back links, information, kinds — answer nothing on their bare space either; folded, the whole form block still goes back, and the Escape key does too.

The editor's form is folded by one clickable reading 'less' while the form shows and 'more' while it is folded. It is five stacked sections: search, back links, information (title, date, brief, use when), kinds, tags — each with its own clickable riding the line above it, all five indented alike. The search section's line is the stack's own leading one, drawn under the section's heavy line. The search section holds a faint gap above its field and a tiny plus a faint below, one gap in all, over and above the half-gap the stack leaves; the field is a box with an edge of its own and needs room a row of plain words does not. The kinds row holds a tiny gap each side, the information rows a small gap below. Every clickable is built by the form, in its own out-of-sight row, never inside the section it folds: a folded section draws nothing, so a clickable built inside it would disappear with the row and leave nothing to press. Search stands bare there — it draws its own section only when something else places it — and folding the whole form now folds the search row with it. The line at the foot of either filter stack is always drawn while that stack is on screen, whatever is folded among its sections — in the editor by the form's own foot, in the list by the count section's heavy edge. Both stacks are told the line below is somebody else's, so a last fold ends against it rather than drawing one of its own. In the list that line is thin (`--thick`) while the tags are folded and heavy while they are open, starved included: folded, what it closes off is a run of accent rather than a row of pills. Browse says that edge once and hands its thickness to the filters' stack as `under`; a shut last section gives back the extra a heavy line takes below the stack's bottom edge, so the line's bottom sits as far from the tags line starved as folded. Folded, each clickable says what it hides: the title, the kind, the tags worn. The kinds line carries a centered 'clear', drawn only while the guide wears a kind; pressing it takes the kind off. The picked kind wears the accent and reads `--text-on-accent`, white on a dark accent and black on a light one, as every other picked thing does.

`use when` holds several occasions, one to a line. It is written into the file as `use_when: [a, b]`, and only when the guide names any; both that structure and one-name-to-a-line are read back.

Nothing in the view column lowers itself with a margin: the page is `flex: 1` and gives back whatever a margin takes. The form's heavy line sits on the region's top edge, its 'more' clickable poking above the border — which required the region and the boxes row to stop clipping (`overflow: visible`); only the window's frame clips now.

The back links live inside the form, below search, standing bare there like search does; the form builds their clickable, which folded says how many guides point here. With nothing pointing here the row does not exist at all — no fold, no clickable. The fold is remembered across visits. Back_Links still draws a section of its own when something places it alone — folded it can take the accent (`accent_when_folded` on Section).

The editor's title tools are four buttons standing centered on the information section's line, hidden only while the whole form is folded — they act on the form's state, so the information section folding leaves them. Its clickable says only 'information', open or folded. Each is a direction: title onto the top heading, top heading into the title, title onto the filename (a rename, lowercased, links and all), filename into the title (capitalized). Their holder on the separator is transparent — each button masks the line for itself, so the line shows through the gaps (`transparent` on Action). The page redraws whenever the body under the labels changes from outside; label-only saves leave it alone. The line's press-anywhere-folds contract is retired.

The top row carries a left-pointing fat triangle beside the hamburger while a file is open — one gap off it, `--size-fat`, 1px `--black` edge on a `--white` body that takes `--hover` under the cursor; pressing it closes the view. Right of it, the file section says where the file sits — every folder above it from the top down, its project first; a file in the memory system starts at its project's folder there, the memory folder itself left off — then the file's name as a field.
