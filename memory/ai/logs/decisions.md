  For: both are live — pull-don't-push says move a thing the day work reaches for it, and today's session reached for both. Git already holds that work and the log holds what is recent.   A middle path, if wanted: `code debt.md` becomes `truth/debt.md` holding only the 27 unchecked items and its done section stays behind, abandoned in place; handoff stops being a file at all — its "what to do next" becomes the current-state paragraph in `index.md` plus `Q:` lines in the log.

- 12 September 2026; **rename label to kvp, for key value pair, for a kind or a tag on a file.** For: it says exactly what the row is, a key and a value, and nothing else, where label says a screen's text and tuple says a count. Three letters, shorter than label, and the shape of the repo's own names, ov, kb, mu, ai, ji, so it reads as one of them. The two specialty tables already head their first column key, so kvp's key is a word the plan uses for the same thing. Nothing in the code or the memory uses it, so a kvps table collides with nothing. Against: it is not a word but three letters, and the always rules ask for everyday or standard technical English, which kvp is only among programmers who spell it out, so every reader outside that room needs it spelled out once, and the lexicon must define it in the same write. It cannot be said aloud as a word, kay vee pee, and it takes no plural without reading as a typo, kvps, nor a compound, the kind kvp, the artist kvp, where the kind label and the artist label read plain. It names two parts, and a labels row has three, name, value and who wrote this, so kvp says less than the row holds, which tuple did not.
