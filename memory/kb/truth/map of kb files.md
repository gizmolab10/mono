# Map of kb files

kb's files, ov's whole since 12 September 2026. Update this when files are added, moved, or removed.

## root config

- [package.json](../../../kb/package.json) — three dependencies, color2k, markdown-it and rbush, and two scripts, check and test. No dev script and no vite config, since a library never runs alone: a host's build compiles kb through the host's own alias.
- [svelte.config.js](../../../kb/svelte.config.js), [tsconfig.json](../../../kb/tsconfig.json) — the compiler and type-check settings, the "core" alias among them.
- [vitest.config.ts](../../../kb/vitest.config.ts) — the test runner: anything ending in `.test.ts` under the source folder, and the alias's second home.
- [CLAUDE.md](../../../kb/CLAUDE.md) — the project entry point.

## src/lib/svelte/main/ — the frame

- [Main.svelte](../../../kb/src/lib/svelte/main/Main.svelte) — the page, which a host's App.svelte draws. Since step 5 it draws panel and hands panel kb's own four: the controls row's right end, the details column, the operation view, and the status line's words and offer, panel drawing the hamburger, the host's name, the two regions' widths and the hover hint. Takes the host's four snippets and hands each down to where it is rendered. Pushes the four theme colors onto the page whenever any of them changes. Shows nothing but "setting up the overview browser..." until the guides are read. Reads the latest build number off the build notes table the host hands over, and holds the backdrop that shows them.
- [Controls.svelte](../../../kb/src/lib/svelte/main/Controls.svelte) — the right end of panel's controls row: panel draws the hamburger and the host's name, and this holds, browsing, a spacer and the two buttons at the right — start the dispatcher over, open the build notes. While a file is open the row instead holds the way back to the list and, past a heavy upright line, the file's own section on the page color: the count, the step marks, the folders above the file, the file's name as a field that reads as plain words, and the four buttons at the far right — make one beside it, hand it to Obsidian, send it in a message, throw it away, the last asked about first. The section's bare space answers nothing.
- [Details.svelte](../../../kb/src/lib/svelte/main/Details.svelte) — the details column's contents, inside panel's region: three things that fold, preferences, repair and the rules, and below them the host's own section where it hands one. Which are open is saved as a list of their names; all shut saves an empty list, and nothing saved at all means all open. A closing line is drawn under the last section only while it stands open.
- [Operation.svelte](../../../kb/src/lib/svelte/main/Operation.svelte) — the operation view's contents, inside panel's region, which gives it its width and height. It shows exactly one of two things: reading a guide, or looking through them, and hands the host's three snippets for it down to where each is rendered. A guide the list no longer shows closes itself rather than showing nothing.
- [Browse.svelte](../../../kb/src/lib/svelte/main/Browse.svelte) — looking through the guides: the filters, the count row, and the list, stacked flush so each holds its own gap and nothing adds a second helping. The count row carries a show/hide folders button at the far left, an unsorted button beside it, and the count pinned to the middle of the whole row. The folders button hides when the filters leave nothing; the unsorted button shows only when the folders are hidden, a sort is on, and more than one file is left.
- [Edit.svelte](../../../kb/src/lib/svelte/main/Edit.svelte) — the frame around one guide: the three parts stacked in it — the label form, the file's own words, and the line along the bottom. The file's controls are the top row's, drawn by Controls.svelte. The host's operation view, where it hands one, is rendered below the label form, given the file and the room. The Escape key goes back to the list, and the arrow keys step to the file before or after. Two things are shared rather than owned by any one part, so they live here: the whole file's text, which both the labels and a piece being changed write to, and the short line along the bottom that says what a dead link or a refused write has to say.

## src/lib/svelte/content/ — what the content box shows

- [List_Files.svelte](../../../kb/src/lib/svelte/content/List_Files.svelte) — the list itself: every folder and file, folders leading their contents, each row indented by how deep it sits. A row's whole width answers to a click — a file opens for reading, a folder opens or shuts — and carries the hover hint; the little triangle keeps its own click and stops it from reaching the row. The column titles are buttons while the folders are hidden: clicking one walks it through smallest first, largest first, and not sorting, and more than one column can sort at once, with a small number saying where each comes in the order. A project column appears between kind and name, but only while the folders are hidden and no project is picked. The header sits still above the scrolled rows and stands only as tall as its line: the line lies along its top edge and the titles are pulled out of the flow to ride it, taking no height, so whatever stands above measures its gap to the line and the rows stand clear below. The header as a whole stands in front of the line, since lifting it makes a world of its own that nothing inside can reach out of. The list remembers where it was scrolled. The line between rows starts well in from the left, painted under the first column rather than drawn as its edge. Whether there is actually a scrollbar is measured rather than assumed, since a stylesheet cannot ask. A file missing from the disk has its name struck through, its hint says so, and a click says so along the bottom and opens nothing.
- [Edit_Markdown.svelte](../../../kb/src/lib/svelte/content/Edit_Markdown.svelte) — one guide's own words. Its text is read here, turned from markdown into a page, held only while it is on screen, and let go on close. A click on any piece opens it in a box holding the file's own words for those lines; leaving the box writes just those lines back. Each heading is named after its own words so a link ending in a heading has something to land on. A click on a link follows it — down the page, to another guide, or out to a new tab — and a link that leads nowhere says why. Every link is registered with the hits manager as it is drawn, so each answers for its own place and its own words; which one was pressed is still worked out from the press. The words are styled here — paragraphs stepped in and spaced, the six heading levels colored, a line under the top heading — and punctuation is left exactly as the file writes it, so a piece reads the same on the page as in the box that edits it. Every heading below the first carries a soft pointer in the left margin that folds its section away, and the top heading's folds them all; the left inset sits inside the scrolled box so those pointers are not clipped away. The bar beside the words carries a second marker showing where the browser alone would have put its thumb. Where a guide was left is remembered as the scrolling settles — the line the topmost piece began on, never a distance — so coming back to it comes back to the same words; the title stays at the box top, so it is passed over when that line is read.
- [Back_Links.svelte](../../../kb/src/lib/svelte/content/Back_Links.svelte) — which guides point at the one being read, each a pill that opens it. A section of its own below the words, drawn only where something points here — an empty one reads as something still being worked out and takes space from the words above it. The gathering is the manager's; this only shows what it worked out.
- [D_Preferences.svelte](../../../kb/src/lib/svelte/content/D_Preferences.svelte) — the accent color picker. **ji**
- [D_Rules.svelte](../../../kb/src/lib/svelte/content/D_Rules.svelte) — the rules section of the details column: every rule the db holds, each with a button that takes it away, and a row to add one — what it reads, the regex, and the kind or tag it gives. Adding or taking one away runs every rule on every file at the dispatcher, and every record here is relabeled from the db.
- [D_Repair.svelte](../../../kb/src/lib/svelte/content/D_Repair.svelte) — two buttons in the details column for putting right what nothing on screen would show as wrong: mending the index files, since a move can only mend the two folders it touched, and looking through every guide for links that lead nowhere. Each says in the log that it was asked for; the work itself is the files manager's.
- [Report.svelte](../../../kb/src/lib/svelte/content/Report.svelte) — words too many for the one line along the bottom, read in the whole content box with space to scroll, and a cross at the top left that takes them away. It says when it was made, since a report is kept across a reload and a week-old one otherwise reads like this minute's. A dead link listed in it opens its guide with the link's own drawn words looked for and lit — its address is never looked for, since only the words are ever on the page — and the back mark then comes here rather than to another file.

## src/lib/svelte/filter/ — narrowing what is shown, and looking inside it

- [Browse_Filters.svelte](../../../kb/src/lib/svelte/filter/Browse_Filters.svelte) — the four filters across the top: words looked for in titles and descriptions, one project at a time, one kind at a time, and any number of tags. The kinds row also offers `none`, which leaves only the files carrying no labels at all. Each has its own bar with its own word above it. The search field takes the whole top row, and the heavy line under it carries one word that folds every picking row at a press — reading just `filters` while they show, and what each holds while they don't. Each row also folds behind its own word. Every fold is remembered. What kinds and tags exist isn't known until the files are read, so both lists fill themselves the moment that finishes. The host's own filter, where it hands one, is the last row, after the tags.
- [Edit_Filters.svelte](../../../kb/src/lib/svelte/filter/Edit_Filters.svelte) — what one guide is labeled: its title, its date, the line saying what it is for, the occasions to read it on, its authors and where it came from, its one kind, and its tags. Nothing is typed as free text where it matters — the kind and the tags are picked from the only lists the app accepts. The line above folds the whole form away and then says what the file is labeled; the kinds and the tags each fold behind their own word too. Any change writes to the db at once, never to the file — the kind and the tags as labels, the four fields on the file's row, the authors and where it came from as its sources — and tells the list, so what is on screen agrees with the db without every file being read again. The host's own rows, where it hands them, sit between the kinds and the tags.
- [Search.svelte](../../../kb/src/lib/svelte/filter/Search.svelte) — looking through the guide on screen: the search row, and the one place highlighted in the words. The count and two step marks appear beside the field once there is something to look for, and walk the places found, wrapping at both ends. The words looked for are the very ones typed into the list's search, so they carry between the two screens and across a reload. A place inside a folded section is shown while it is highlighted; the piece already open is left alone when the next place is inside it, since folding and unfolding the same piece is what blinked on every keystroke.

## src/lib/ts/ — logic

- [common/Core.ts](../../../kb/src/lib/ts/common/Core.ts) — everything kb adopts from core, one line each, reached through the "core" alias that tsconfig, vite.config and vitest.config all name. Through it come the one source for every size (`k`), the call that mirrors those numbers onto the page, the color math and the four theme colors, the additions to text and number handling, the diagnostic log, and — adopted 31 August 2026 — a title riding a separator, a press with what was held down alongside it, the sections of the details column, what a thing under the cursor is, the shared types, how much of a run of words fits, a number written in thousands, which pieces a heading owns, a box growing to its natural height, where a scrollbar's thumb would have been drawn, angles and their directions, points and rectangles, the whole hits manager and the element that registers with it, the timers behind a long press and a held repeat, the drawn shapes, the arithmetic behind a section and the spacing of the lines across a view, the rules behind the step marks, the hover hint's plumbing, and six components — a section, a separator, the steppers, the hint itself, the pill that holds one area of tags, the line of words along the bottom, the build-notes popup — which is handed its table by App, since core names no file inside a host — the stack of sections, and the hamburger, which takes its name, its press and its hint as props and wears the two class names ov styles from Controls.svelte. The global stylesheet comes from core too, imported by the host's main.ts as `core/main.css`, since a library has no entry file, and one section of a stack is core's type. Nothing in kb is a second copy of anything in core. Only this file reaches through the core alias, and Panel.ts alone through panel's; every other kb file imports from the two, components included. **⟵core**
- [common/Panel.ts](../../../kb/src/lib/ts/common/Panel.ts) — everything kb imports from panel, one line: the page, Panel.svelte, which Main.svelte draws. **⟵panel**
- [common/Customizations.ts](../../../kb/src/lib/ts/common/Customizations.ts) — the facts a host hands kb before anything mounts, one field each, as adopt kb's table lays them out: the name the controls row shows, the prefix remembered values are saved under, the host whose db the dispatcher answers from, the kinds, tags and tag areas, the hierarchies the list offers, each a label and the order within a group, and the build notes table. The defaults name no host.
- [managers/Files.ts](../../../kb/src/lib/ts/managers/Files.ts) — where the guides come from. The dispatcher is asked what markdown files sit under every collection's guides and designs folders, and that list is the whole picture — nothing is settled when the app's code is prepared, so a file added, moved or thrown away shows straight away. Every file is hung from that listing first, so the list draws before a text is read; then each file is read once — a few at a time, the edited file and the rows in view ahead of the rest — for the links it holds and its size, its text let go, the list narrowing as each batch arrives. Its five labels come from the db, asked for in one answer beside the listing, never from the file's own top: the kind and the tags as labels, the title, description, use_when and date as the four fields on its row — and a change to any of them goes to the db, one write per label put on or taken off and one for the fields. A file the db has no row for is unlabeled, its name its title, and gets its labels composed from its own words and marked stale the first time it is opened for editing. A file the db marks missing from the disk hangs where it sat, with no address and nothing read for it, so the list shows it. Every file's sources, its authors and where it came from, are kept beside the labels for the editor, and written back through the db. A hand kind wins over one a rule gave, the tags are both together, and what the AI suggests is passed over until it is accepted. After a rule changes, every record is relabeled from the db without a read of the disk. Index files are left out entirely. It also keeps every guide's own links, taken out of that same text at launch, and works out from them which guides point at which — the double-bracket form turned into the ordinary one first, and each link answered by the same following that answers a press. After a write, the changed guide's links alone are followed again and the map mended for it, since 13 September 2026. Also renames, moves and throws away a guide — mending the links and the index beside it — and hands out the rows the hierarchy worked out, working them out again whenever any filter moves.
- [managers/Hierarchy.ts](../../../kb/src/lib/ts/managers/Hierarchy.ts) — the folders, the files, and the tags on them, made fresh each launch out of the addresses. Holds the walk that turns the folder structure into a list with a depth on every row, and the narrowing: which rows survive the filters, which folders are kept because something inside them matched, how many matching files sit under each folder, and the sort. It also answers a link written inside a guide, by climbing the folders above that guide and taking the first guide of that name found beneath any of them. And, for a report alone, says which file a link that nothing answers most likely meant — never for a press, which must be exact. **⟵ji**, with the storage left behind.
- [managers/Filters.ts](../../../kb/src/lib/ts/managers/Filters.ts) — all the filters in one place, so the hierarchy can read them without reaching into anything that draws: the project, the kind, the tags and which way they pick, the words, which folders are shut, whether folders show at all, and which columns sort and which way. Also the three plain answers behind them — whether a file survives the picked tags, what turning them over leaves picked, and which remembered words are still among the choices — each written over plain lists so it can be proved without a page.
- [managers/Operations.ts](../../../kb/src/lib/ts/managers/Operations.ts) — which of the two things the content box is doing, which guide is being read, and the stepping between guides. Off the list it walks the stack of guides reached by links — one down, one up, emptied by backing out of the bottom; on the list it walks the filtered run, past folders and wrapping at both ends. Each walk is two halves — one says which file lies a step that way, the other goes there and asks the first — so what a stepper says it would open and what pressing it opens are one answer. It also keeps, for each guide, the line that stood at the top of its words when it was last left, so coming back to one comes back to where the reading was — held with the settings, so the guide being read survives a reload scrolled. **⟵ji**, trimmed from seven modes to two.
- [managers/Status.ts](../../../kb/src/lib/ts/managers/Status.ts) — whether there is anything to say along the bottom, and what. One call says a line and starts the few seconds after which it clears itself. What a report found is remembered along with those words, so a reload comes back to the whole report rather than its first line with nothing under it.
- [managers/Preferences.ts](../../../kb/src/lib/ts/managers/Preferences.ts) — what the browser remembers between visits. Every name reads `ov_` then the parts joined by underscores, and the name in the code is the name in the browser. None of ji's renaming and sweeping code came over: overview has no old names to bring forward.
- [database/Indexes.ts](../../../kb/src/lib/ts/database/Indexes.ts) — the instant lookups (tags by file, files by tag, children by folder, parents by file), rebuilt whenever the records change. **⟵ji**
- [types/File.ts](../../../kb/src/lib/ts/types/File.ts) — what a file is: the five labels off a file's top, its kind one word off the host's kinds and its tags off the host's closed list, both handed in the configuration since step 7 of the plan, the collections, and a listed row — a file together with the tags on it, how deep it sits, the folder chain above it, and whether it holds anything. The record is called a file rather than a guide, since the list holds work notes too.
- [types/Tag_Areas.ts](../../../kb/src/lib/ts/types/Tag_Areas.ts) — the shape of a tag area, the tags gathered into areas so many words can be read a handful at a time, and the answers over any host's lists: which area a tag belongs to, which tags no area claims, which of an area's tags are still worth showing, and what a shut area reads. The areas themselves are the host's, handed in the configuration since step 7 of the plan, ai's ten among them, and ai's tag areas test proves its two lists agree.
- [types/App.ts](../../../kb/src/lib/ts/types/App.ts) — the two states the app can be in: setting up, and ready.
- [types/DB_Records.ts](../../../kb/src/lib/ts/types/DB_Records.ts) — the record structures the hierarchy keeps: tags, tag placements, folder links, and link meanings. **⟵ji**
- [utilities/Markdown_Blocks.ts](../../../kb/src/lib/ts/utilities/Markdown_Blocks.ts) — turning a guide's text into the page on screen, and putting a change back into that text. Takes the five labels off the top; gives every outermost piece two numbers counted from zero against the whole file — the line it starts on and one past the line it ends on — plus the line it begins on counted from one for showing — the whole file, the labels among the lines, so it reads the same as Obsidian's own number for that line — and how deep it sits. Names the headings, gives every link the words its hover says — the name of the file it goes to, without the folders above it or its ending — draws a list item's brackets as a box and turns one over on a press, and draws a rule as an ordinary row so it can carry a number. Says every link a guide's words hold as two things — where it points, and the words it reads as — since only the words are ever drawn. Also hands one piece's own words back out of the file, swaps a run of lines for what was typed leaving every other line untouched, and answers whether those lines still read as they did when the piece was opened. A list item is told the one line it begins on; everything else sitting inside another piece is left unmarked. Also says what markdown stands at the head of a line that the drawn page gives no width to — a heading's hashes, a thing to be done's bullet and brackets — so the box that opens over that line can stand them out to the left.
- [utilities/Index_Files.ts](../../../kb/src/lib/ts/utilities/Index_Files.ts) — mending the two index files a move leaves lying: reading which file a bulleted link names, taking that line out of one index, and putting it into another in its alphabetical place. An index that lists files in more than one place gets a "More" heading, since nothing in it says which list the arrival belongs to.
- [utilities/Emphasis.ts](../../../kb/src/lib/ts/utilities/Emphasis.ts) — making a run of picked words heavy, slanted or struck through while a piece is open, and taking the marks off again. Stars stack — one is slanted, two are heavy, three are both — so slanting heavy words adds to them rather than half-undoing them. Also the marks that come in pairs: typing a bracket, brace or quote with words picked puts it before them and its partner after, and typing it again takes both off.
- [utilities/Searching.ts](../../../kb/src/lib/ts/utilities/Searching.ts) — which piece a search has to open and which it can fold away again, worked out together from the piece open now and the piece the next place needs. Done in the wrong order it folded a piece and opened the same one again on every keystroke, which is what blinked.
- [utilities/Labels.ts](../../../kb/src/lib/ts/utilities/Labels.ts) — the five labels as plain work on text, needing nothing on screen: reading them off a block a file's top may still carry, in either structure a list can be written in, and composing them for a file that has none from its own words — its first heading, its first sentence, today, the fallback kind, analyze, ai's word here until step 12, and the tags that say it is new and needs a look. The writers of a block stay here, called by nothing since 10 September 2026, when the labels moved into the db and every block left the files. A brand new file is its heading alone. Also says which labels to put on and take off in the db to carry a file's kind and tags from what they were to what they are now, over plain words.
- [utilities/Saving.ts](../../../kb/src/lib/ts/utilities/Saving.ts) — writing a changed file back to its own place. Works out where a guide, a design, a work note or a file in mono's tooling folder sits counting from the top of the repo, and the other way round — the tooling folder's own files answer to mono whatever their ending, since a hook is a shell script and a setting is json — a work note where the dispatcher's plugin lists it, since step 6 of the plan; where a file lands when it is dropped into a folder or given a different name; and hands the dispatcher the whole new text along with the text as it was when the file was opened — which that server checks against the file before writing anything. And asks the dispatcher to start itself over, waiting until it answers again. The db's side too: every label, every file's four fields and its sources in one ask, one label put on or taken off a file, a file's four fields written on its row, its sources made exactly what is sent, and the rules listed, added to and taken from. Every ask names the configured host, so the dispatcher answers from that host's db, ov's when none is configured.
- [utilities/Tag_Rows.ts](../../../kb/src/lib/ts/utilities/Tag_Rows.ts) — whether any tag area in the topmost line of a run shows its own name riding above its top edge. That name reaches up out of the pill, so the run holds a gap above itself to keep it off whatever runs overhead — and only a name in the top line reaches anything. The pills wrap, so which line each is on is measured; the reckoning is written over plain numbers so it can be proved without a page. No caller since 5 September 2026 — both filter files hold the gap always; reported, not removed, its test still passing.
- [utilities/Following_Links.ts](../../../kb/src/lib/ts/utilities/Following_Links.ts) — the two questions a link raises, kept apart on purpose. Whether the file found really answers it: a link naming only a word takes any file of that name, one naming folders must land under exactly those. And, where nothing answers exactly, which file it most likely meant — most shared words first, ties broken by the fewest folder steps from the file the link sits in, and nothing at all offered where two are equal on both. The first answers a press and refuses; the second only ever names a candidate in a report.
- [utilities/Opening_Code.ts](../../../kb/src/lib/ts/utilities/Opening_Code.ts) — handing a piece of the code to VSCode. A guide often names the very file it describes, and those files are not guides, so nothing in the collection answers for them. This says which links name code, works out where that file sits by climbing out of the folder of the guide naming it, and reads the line off the end of the link.

## src/ other

- [vite-env.d.ts](../../../kb/src/vite-env.d.ts) — the ambient types that let the build's raw-text and address imports type-check.
